# Real API Integration Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task.

**Goal:** Serve the normal preview from the persistent Rust API while preserving all approved frontend behavior.
**Architecture:** BeeApi remains the UI port. A dedicated HTTP transport handles headers/errors/binary data; HttpBeeApi maps resource operations to official endpoints. Mock is explicit opt-in for tests/demo only. Vite proxies /api to the local backend.
**Tech Stack:** React, TanStack Query, Fetch, Vite, Rust HTTP API.
**Spec:** Authorized coordinator message and frontend/contracts/* OpenAPI.

## Constraints
- No authentication, deployment, remote publication or destructive cleanup.
- UUID internals, canonical slugs, query navigation, theme .625rem and existing icons stay intact.
- X-Actor-Kind: human; strong If-Match versions; idempotent POST keys per intent/reused on retry.
- Do not silently fall back to mock or hide backend errors.

## Review focus
- Global task children across boards; resource-specific filters must match endpoint allowlists.
- Status update needs board scope; ordering uses board version.
- Conflict/network/non-JSON errors retain meaningful UI feedback.
- Failed creation retry must not duplicate a successful but lost response.
- Binary image/download responses and persisted edit after reload.
