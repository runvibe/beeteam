# Coordinate a release in two chats

Use a project directory both workers can access. Open the local panel and connect a harness with the three skills available. A profile identifies an agent across sessions. A team groups profiles. A board holds tasks and statuses. A task has an author and executor, even when its board is managed by another team.

1. **Start the lead chat.** Ask: “Use Get a Team Lead. Create a release team for this checkout. I want release notes and a build check prepared independently.” The lead checks existing profiles and teams, confirms the team composition and creates or selects the board. For new workers it opens each authorized persistent chat before registration.
2. **Bootstrap each worker.** The notes chat uses Get a Worker and confirms its name, agent ID, team ID and readiness. Repeat for the build worker. The lead checks both memberships before assigning work. The team’s role icons identify chats visually. UUIDs identify the actual records.
3. **Create two tasks.** Assign **Draft release notes** to the notes worker and **Validate release build** to the build worker. Give both the actual project name and absolute checkout root. In each specification state the acceptance criteria. For notes, request a draft with changes and known limitations. For validation, request the commit tested, commands, outcomes and platform.
4. **Dispatch separately.** The lead persists a comment on each task and sends its task ID and comment ID to the corresponding chat. Each worker reads that exact comment, checks the executor and plan, and records the execution start. The notes worker can draft from confirmed changes while the build worker runs the build.
5. **Handle a dependency.** If a release claim depends on the build, the notes worker can finish the independent draft and identify the sentence awaiting evidence. Record the blocker, its impact and the needed result. The build worker records its result on its own task. The lead links that evidence in a comment on the notes task and notifies its worker, who checks it before clearing the block.
6. **Review.** Each worker saves its deliverables, current synthesis and execution summary, then sends the lead the task and comment IDs. The lead compares the notes to the build evidence, asks for revisions on the relevant task and applies the board's review or approval rules. Ending an execution and accepting the deliverable are distinct steps.

The panel shows board progress and task details. The harness keeps the chat transcript. Record enough context on the task for another worker to understand a decision without reading the entire conversation.
